# html-storyslides：用 HTML 簡報說明一個主題、表達觀點

## 流程

### 1. 收集素材

**只用使用者找到的參考資料當來源，不要自己上網查新的資料。**

1. 來源只有：使用者在對話中提供的資料（連結、檔案、貼上的內容），以及 `output/<主題>/research.md` 中已有的資料與 [編號]。
2. 唯一可以上網查的情況：使用者引用或提到某份資料，但沒給全文或連結（例如「那篇 2019 年的論文」「〇〇的原始定義」）→ 只查那一份資料本身，找到後列入參考資料。不要順便找其他來源。
3. 素材不足以支撐某一頁時（例如缺數據、缺出處），不要補查，在討論大綱時告訴使用者缺什麼，由使用者決定要補資料還是刪掉該頁。
4. 使用者的看法：從對話中取得。沒有明確立場時，做成「中立說明型」簡報（把「我的看法」頁改成「重點整理」）。

### 2. 規劃故事線，和使用者討論大綱

**先和使用者討論出大綱，確認後才開始寫 HTML。** 不要直接產生檔案。

1. 依下方架構擬一份大綱草稿，在對話中用表格列出每一頁：章節、頁標題（符合第 3 節的標題規則）、這頁要講的一句重點、用到的參考資料編號 [n]。
2. 附上簡報類型、預計頁數、貫穿全場的圖像（類比），並提出你不確定的地方（例如要不要放互動示範、計算案例的規模、哪些內容可以省略）。
3. 等使用者回覆。使用者要求增刪或調整時，修改後再列一次，直到使用者明確同意（例如「可以」「就這樣做」）。
4. 使用者已經提供完整大綱時，仍要整理成上述表格請使用者確認一次。

先判斷簡報類型。使用者指定了架構時，一律以使用者的架構為準。

**A. 說明型（技術、演算法、科學概念）**：最常用，範例見 `output/ficks-law-algorithm/slides.html`

| 章節（`slide section`） | 內容                                                                       |
| ----------------------- | -------------------------------------------------------------------------- |
| 封面                    | 正式名稱當標題，一行副標題說明它是什麼                                     |
| 名詞介紹                | **放在最前面**：一頁圖解最核心的概念，加一頁名詞一覽表（名詞／意思／圖解） |
| 〇〇由來                | 為什麼需要它、發展年表、屬於哪一類、相關的重要理論或批評                   |
| 〇〇原理                | 靈感來源的真實現象（含具體例子與影響因素），再對照它實際借用了什麼         |
| 〇〇步驟                | 概要、流程、各階段公式、參數                                               |
| 計算案例                | 小規模手算例，數字一定要用程式實際算過                                     |
| （其他）                | 互動示範、實作注意事項、重點整理、參考資料                                 |

**B. 觀點型（發表看法）**：封面 → 為什麼要談 → 背景 → 論點 1–3（大字主張 + 證據）→ 另一種看法 → 我的回應 → 結論 → 參考資料。

不論哪一型，**一頁只講一件事**。

### 3. 寫作與風格規則（使用者偏好，優先於其他設計建議）

**標題**

- 標題用**短名詞片語**，不要用句子，也不要精簡到只剩一個字詞。
  - 好：「名詞介紹」「演算法由來」「計算案例」「影響擴散速率的因素」「擴散與 FLA 的對照」「第 1 代擴散計算」
  - 太長（句子）：「擴散有多快，由五個因素決定」
  - 太短：「名詞」「由來」「計算例」
- 章節頁（`slide section`）**不加「一、二、」編號，也不加副標（kicker）**，只放章節名稱。
- 封面要有一行副標題（`.subtitle`），例如「以物理擴散定律為啟發的找最佳解方法」。
- 原本想放在標題裡的結論，要寫進該頁內文（第一行或 `.callout`），不能因為標題縮短就消失。
- 除了封面與章節頁，**每一頁都要有 `<h2>` 標題**。只放大數字或一張圖的頁面也不例外，例如「聲音資料的記憶體大小」。
- 大數字頁的每個數字都要附 `.big-label`，說明它是什麼的數量（哪個場景、哪種方法），並用 `.callout` 說明這些數字代表什麼、為什麼重要。
- 章節名稱要和章節內的頁面相符。例如「名詞介紹」章節只放名詞與概念圖解，不要接方法的架構圖；架構圖放到該方法的章節，標題取「〇〇架構總覽」。

**讓人看得懂**

- **先解釋名詞，再講其他內容**。後面用到的專有名詞都要能在名詞一覽表中找到。
- **英文縮寫要顯示全名**：縮寫（例如 DO、EO、SSO）列入名詞一覽表並寫出英文全名與中文意思；在概要卡片、該縮寫的專屬頁面第一行、互動示範的狀態文字中也要顯示全名，例如「DO = Diffusion Operator（擴散算子）」。全名要有出處。
- 用一個貫穿全場的具體圖像說明抽象概念，例如最佳化就是「在地圖上找最低點」。
- **類比必須與實際機制方向一致**。如果靈感來源和實際做法不同（例如擴散是散開、最佳化是聚集），要直接用一頁對照表說清楚「它不是在模擬什麼、只借用了什麼」，不要硬套比喻。
- 介紹真實現象時，用生活中的具體例子和影響因素說明（例如肺泡的氣體交換、濾網大小、窗簾厚薄）。
- 公式頁下方加一行 `.callout` 的「白話」說明，用貫穿全場的圖像描述這一步在做什麼。

**精簡**

- 簡報**盡量精簡**：頁數越少越好，能合併的頁就合併，和主軸無關的頁就刪掉；擬大綱時就先砍。
- 內文每頁最多 3 個重點、每點盡量一行；細節放進講者備註。
- 能用圖說明的就用圖，不要用一段文字。

**引用來源的圖片與圖表**

- 參考資料中有圖片、圖表、示意圖、表格時，**優先直接引用原圖**，不要自己重畫或改寫成文字。只有來源沒有合適的圖時，才自己畫。
- 擬大綱時在表格中註明每頁要用哪張圖（例如「[2] Fig. 3」）。
- 圖片存到 `output/<主題>/images/`，檔名用簡短英文（例如 `ref2-fig3.png`），HTML 用相對路徑引用。
  - 網頁上的圖：下載原檔。
  - PDF 中的圖：用 `pdfimages` 擷取，或把該頁轉成圖片後裁切出圖的範圍。
- 每張引用的圖都用 `<figure>` 包起來，`<figcaption>` 寫一行說明加出處，例如「擴散速率與溫度的關係（[2] Fig. 3）<sup class="cite">[2]</sup>」。
- 放好後用 Read 打開圖片檔確認內容正確、沒有裁錯。

**內容**

- 有數據就用 `.big-number` 做成大數字；有對比就用 `.compare` 兩欄、三類並列就用 `.three`。
- 所有事實後面加 `<sup class="cite">[n]</sup>`，對應參考資料頁的編號。
- 不捏造數據或來源；自己的推導或實驗要寫明「我的推導」「我的實驗」。
- 演算法主題要附互動示範，並允許調整點的數量等參數；示範程式要依可信的實作移植，並用 Node 實際跑過，確認會收斂。
- 預設繁體中文。

### 4. 產生檔案

1. 複製 `assets/template.html`（與本 SKILL.md 同目錄）作為基底，**保留其 CSS 與 JS**，只替換 `<main id="deck">` 內的 `<section class="slide">`，並改 `<title>`、`<meta name="description">`（一句話簡介）、`<meta name="date">`（今天日期）與 `<meta name="category">`（分類）——首頁會讀這四個欄位。
   - **分類**：只能用使用者設定的分類標籤，清單在 `scripts/build-site.mjs` 的 `CATEGORIES`（目前只有「資訊」）。不要自己新增分類，也不要分得太細。主題對不上任何標籤時就不寫 `category`，首頁會把它列在「其他」；使用者要新增標籤時，再加進 `CATEGORIES`。
2. 輸出到 `output/<主題>/slides.html`，與 research.md 放在同一個主題資料夾（目錄不存在就建立）。`<主題>` 用簡短的英文 kebab-case（會成為網址），與 research-sources 用的資料夾名稱一致。
3. 範本右下角有「目錄」與「參考資料」連結；該主題沒有 research.md 時，刪掉「參考資料」那個連結。
4. 每頁可加講者備註：`<aside class="notes">...</aside>`（按 `N` 顯示 / 隱藏）。
5. **依主題調整外觀**：範本的米白加橘色只是預設值。製作前先參考 `frontend-design` skill，為主題定出配色與字體（可從 `theme-factory` 挑選）。做法是在範本的 `<style>` 之後再加一段 `<style>`，覆蓋 `:root` 的色票（淺色與深色兩組都要寫），不要改動範本原本的 CSS。
6. 有數學式時，從 cdnjs 載入 KaTeX（`katex.min.css`、`katex.min.js`、`contrib/auto-render.min.js`），用 `\( \)` 與 `\[ \]` 標記。
7. 範本已處理好翻頁操作：鍵盤 ← →、滑鼠點投影片任何地方（左半部上一頁、右半部下一頁，滑鼠所在那側會出現 ‹ › 提示）、手機滑動、右下角按鈕。點連結、按鈕、選單、畫布或剛選取文字時不翻頁；互動示範等整塊不該翻頁的區域加上 `class="no-flip"`。點過按鈕或改過選單後鍵盤仍可翻頁。範例可參考 `output/ficks-law-algorithm/slides.html`。

範本提供的版型 class：

- `slide cover`：封面
- `slide section`：章節過場（大字置中）
- `slide`：一般內容頁
- `.big-number` + `.big-label`：大數字
- `.compare` 內放兩個 `.col`：正反 / 前後對照
- `.three`、`.formula`、`.callout`、`table.data`、`.steps`：範本沒有內建，可從 `output/ficks-law-algorithm/slides.html` 的主題 `<style>` 複製
- `blockquote` + `<cite>`：引用
- `.refs`（`<ol>`）：參考資料清單
- `figure` + `figcaption`：引用的圖片。範本沒有內建，在主題 `<style>` 加上：
  `figure{margin:0;text-align:center} figure img{max-width:100%;max-height:60vh;object-fit:contain} figcaption{font-size:.8em;opacity:.7;margin-top:.5em}`

### 5. 檢查

- 用 Bash 確認檔案存在、`<section class="slide"` 數量符合預期。
- 確認每個 `[n]` 都能在參考資料頁找到。
- 確認每個 `<img>` 的檔案都存在於 `output/<主題>/images/`，且每張圖都有 `<figcaption>` 標出處。
- 列出所有 `<h1>`、`<h2>` 標題，逐一檢查是否符合第 3 節的標題規則。
- 告訴使用者：檔案位置、頁數、操作方式（鍵盤 ← → / 空白鍵翻頁、滑鼠點畫面左半部／右半部翻頁、`F` 全螢幕、`N` 備註、`Ctrl+P` 存成 PDF），並用 2–3 句說明故事線。

### 6. 發布（使用者同意後才做）

`output/` 會透過 `.github/workflows/pages.yml` 自動發布到 GitHub Pages，部署時 `scripts/build-site.mjs` 會自動產生首頁目錄 `output/index.html`（左側依分類列出所有簡報並可搜尋，右側直接預覽，網址 `#deck=<資料夾>&cat=<分類>` 可分享），並把每個 `research.md` 轉成閱讀版的 `research.html`（兩者都不進 git）。本機預覽：`npm install`（第一次）→ `npm run build` → 開 `output/index.html`。

詢問使用者是否要發布；同意後：

1. `git add output/<主題>` 並 commit（訊息如 `新增簡報：<標題>`）。
2. `git push` 到 `main`，Actions 會自動部署。
3. 告訴使用者網址：`https://<GitHub 帳號>.github.io/<repo 名稱>/<主題>/slides.html`（帳號與 repo 名稱從 `git remote get-url origin` 取得）。
